# Husky Setup

Git hooks for this project, managed by [husky](https://typicode.github.io/husky/) v9.

## What runs, and when

| Hook | Command | Runs on |
| --- | --- | --- |
| `pre-commit` | `npm run lint` | `git commit` |
| `pre-push` | `npm run build` | `git push` |

`pre-commit` is kept fast so committing stays painless. `pre-push` is slower but runs far less often, and `build` is `tsc -b && vite build` — one command that catches type errors *and* proves the bundle compiles. That is the same thing [the GitHub Pages workflow](.github/workflows/deploy.yml) does on every push to `main`, so failures surface locally instead of as a red CI run.

Both hooks check the whole repo, not just staged files.

## If you just cloned this repo

Nothing to do:

```bash
npm install
```

The `prepare` script in [package.json](package.json) runs `husky` automatically after install, which reinstalls the hooks. `prepare` does not run in CI (`npm ci --omit=dev`) or for consumers installing this as a dependency, which is what you want.

## Setting this up in a new React project

Order matters — husky writes into `.git/`, so the repo must exist first.

```bash
# 1. Create the project
npm create vite@latest my-app -- --template react-ts
cd my-app
npm install

# 2. Initialize git BEFORE husky
git init
git add -A
git commit -m "chore: initial commit"

# 3. Install husky
npm install --save-dev husky
npx husky init

# 4. Replace the default hook and add pre-push
echo "npm run lint" > .husky/pre-commit
echo "npm run build" > .husky/pre-push

# 5. Verify before a real commit depends on them
sh .husky/pre-commit
sh .husky/pre-push

# 6. Commit — .husky/ must be tracked
git add .husky package.json package-lock.json
git commit -m "chore: add husky pre-commit and pre-push hooks"
```

### What `npx husky init` does for you

- adds `"prepare": "husky"` to package.json
- sets git's `core.hooksPath` to `.husky/_`
- creates `.husky/pre-commit` containing `npm test`

**Fix that third one.** The Vite React template has no `test` script, so every commit would fail until you overwrite it. That is what step 4 above is for.

## Skipping a hook

```bash
git commit --no-verify -m "wip"
git push --no-verify
```

Use sparingly — CI runs the same checks and will catch what you skipped.

## Troubleshooting

**Hooks do not run at all.** Check that git is pointed at the right directory:

```bash
git config core.hooksPath   # should print .husky/_
```

If it is empty or wrong, run `npx husky` to repair it.

**`.husky/_` is missing.** It is gitignored by design and regenerated by `npm install`. Run `npm install` (or `npx husky`).

**A hook fails but the command works by hand.** Hooks run in a non-interactive shell that does not load `~/.zshrc`, so anything depending on a shell alias or a PATH entry set in your profile will not resolve. Use `npm run <script>` rather than calling binaries directly.

**Teammates get no hooks.** The `.husky/` directory must be committed. Confirm with `git ls-files .husky`.

## Notes on husky versions

This project uses husky v9, where hook files are plain shell fragments — no `#!/usr/bin/env sh` shebang, no `. "$(dirname -- "$0")/_/husky.sh"` line, and no `chmod +x` needed. Older guides showing `npx husky add .husky/pre-commit "npm test"` describe v8; that subcommand is deprecated.

## Possible next step

Once linting the whole repo gets slow, scope it to staged files:

```bash
npm install --save-dev lint-staged
npm pkg set "lint-staged[*.{ts,tsx}]"="eslint --fix"
echo "npx lint-staged" > .husky/pre-commit
```
